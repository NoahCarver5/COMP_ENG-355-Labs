# sprite_rom

Read-only M20K BRAM holding the game's 32×32 pixel sprites, initialized from a .mif file.

## Ports

| Port | Dir | Width | Description |
|------|-----|-------|-------------|
| `clk` | in | 1 | 100 MHz system clock |
| `addr` | in | 11 | Sprite index (3-bit) + pixel offset (5-bit row, 5-bit col) |
| `data` | out | 24 | RGB888 color; `0xFF00FF` = transparent |

## Address Map

```
addr[10:8]  = sprite ID (0–7, only 0–2 used initially)
addr[7:5]   = row within sprite (0–31)
addr[4:0]   = column within sprite (0–31)
```

| ID | Sprite |
|----|--------|
| 0 | Mole |
| 1 | Hammer (cursor, neutral) |
| 2 | Hammer (cursor, strike flash) |

## Behavior

- Synchronous read: `data` is valid 1 cycle after `addr` is presented.
- Initialized at synthesis time from `sprites.mif` (Quartus .mif format, hex RGB888 per word).
- Transparent pixels (`0xFF00FF`) are passed through as-is; renderer handles the transparency.

## Notes

- `sprites.mif` is generated by `sw_model/png_to_mif.py` from source PNGs.
- 8 sprites × 32×32 = 8192 words × 24 bits ≈ 24 Kbytes → fits in 1–2 M20K blocks.
- If Quartus does not infer M20K from string generic, switch to a VHDL constant array initialized from the package.
